# Foundry deep codebase scan — 2026-09-16 (line-by-line pass)

Scope: entire `anvil` repo, read end to end — Swift package `Sources/` (122 files, ~32,900 LOC across `Foundry`, `FoundryDomain`, `FoundryServices`), `Tests/` (39 files, 7,431 LOC — every test file read), the `anvil/` Next.js site (~1,950 LOC app code, all TS/TSX), `scripts/` (3 files), `Package.swift`, `Supporting/`, CI workflow, resources, docs inventory.

Method: `periphery scan` 3.8.0 (full index build) + `knip` + `eslint` + clean `swift build` (zero warnings), then a manual line-by-line read of every file above, with caller tracing for every dead-code suspect before classifying it.

**Verdict:** unusually disciplined codebase. Zero compiler warnings, zero `print`, zero TODOs, eslint clean, real test coverage with strong state-machine and cancellation tests. The findings are: one class of per-keystroke waste (expensive objects rebuilt inside the search path), a duplicated test-only search implementation that ~20 tests exercise instead of the production path, ~600–900 LOC of provable dead code, and a small set of slop tests (string-contains file assertions, one tautology, presence checks).

**Corrections to the earlier hotspot pass** (the line-by-line read invalidated these):

- `keyName(for:)` is ~18 lines, not a 303-line switch — earlier awk estimate was wrong. Removed from the fix list.
- "Zero force unwraps" was wrong: `SearchScoring.isBetter` has two (`~:442`, `~:459`, safe-by-invariant), `AgentHookBridge.normalizeCommandHook` has a guarded `agentID!`.
- `CommandIconRepository` is **not** off-main: `image(for:)` runs `NSWorkspace.icon(forFile:)` inside `Task { @MainActor in }` — coalesced and cost-bounded, but the IconServices call still executes on the main thread.
- `commandCatalog` **is** consumed (by `CommandSettingsCatalog` via `CommandPanelState:301`) — only the individual descriptor fields are write-only, not the chain.
- `MediaNetworkPolicy` core methods are all live — the dead surface is the `MediaArtifactFileSystem` protocol (`createFile`, `append`, `temporaryFile`, `reserveFile`).
- `provider.descriptor.availability` is live (scheduler fallback gating, `CommandRegistry:360`).

## 2. Performance

Theme unchanged: **work rebuilt per keystroke that should be built once.** Ordered by user-facing impact.

### 2.1 `NSDataDetector` allocated per call — HIGH

`MediaDownloadProvider.mediaURLs(in:)` builds `try? NSDataDetector(types: .link)` inside the function (:61) — one of Foundation's most expensive initializers. Called ~4–6× per keystroke via `isActive(for:)` in both search phases, `isMediaQuery`, `applySearchResults`, `refreshResults`. One-word fix: `static let`.

### 2.2 `NSRegularExpression` compiled per call — MEDIUM

`CalculatorProvider.swift:138,160` (currency parse/convert, inside a pattern loop, on the immediate-tier 80ms budget). Same pattern in `DeveloperToolsEngine`: `dateFormatters()` builds **6 `DateFormatter`s per call** and `splitWords` compiles a regex per call. Eight other regexes in the codebase are correctly `static let`; these missed it.

### 2.3 Two synchronous cross-process AX calls per keystroke, system-wide — MEDIUM-HIGH

`SnippetExpansionService.isSecureTextFieldFocused()` (:157-169) runs two `AXUIElementCopyAttributeValue` IPC calls into the frontmost app on the event-tap callback (main run loop, :81). Every keyDown in any app pays it. `IsSecureEventInputEnabled()` answers the same question with no IPC. A slow target app adds latency to system-wide typing; a hung one risks `tapDisabledByTimeout`.

Minor: `String(UnicodeScalar(NSDeleteCharacter)!)` allocates per keystroke (:135).

### 2.4 Synchronous icon/image work inside SwiftUI `body` — MEDIUM

- `IconCache.shared.icon(forFile:)` → sync `NSWorkspace.icon(forFile:)` on the main actor, called from `body`: `PanelRowViews.swift:299`, `FileShelfView.swift:216,295`, `FileConversionView.swift:69,117`. Cache miss = ~1–5ms IconServices IPC per visible row on first render.
- `ClipboardInlinePreview` decodes `CGImageSource` thumbnails synchronously in `body` (signature-cached, but first decode per image hitches).
- `CommandIconRepository` is the intended fix but **doesn't actually go off-main** (`Task { @MainActor in NSWorkspace.icon(forFile:) }`) — it adds coalescing + `countLimit`, not thread relief.
- `IconCache` and `ClipboardInlinePreview.imageCache` set **no `countLimit`/`totalCostLimit`**; decoded NSImages are w×h×4 bytes.

### 2.5 Synchronous `lsof` spawn per keystroke on port queries — MEDIUM

`MacUtilitiesProvider.PortUtility.lookup` runs `/usr/sbin/lsof` via `runSynchronously` (2s timeout) for `port N` queries — a process spawn inside the immediate search phase for every keystroke completing the query. Bounded by the provider timeout, but it serializes a subprocess into typing.

### 2.6 AI chat markdown reparse per streaming delta — LOW-MEDIUM

`QuickAIView.AIFormattedText` runs a full markdown parse inside `body` for every message; `QuickAIState` throttles deltas to ~33ms, so during streaming the entire thread's markdown is reparsed ~30×/sec. Cache parsed blocks per message or parse incrementally.

### 2.7 Provider-gate head-of-line wait — LOW-MEDIUM (design)

`ProviderExecutionGate.task(for:)` (CommandProviderScheduler:267-274) cancels the in-flight call then **awaits it** before starting the next — a provider ignoring cancellation serializes its stall into subsequent keystrokes. Bounded by phase timeouts; self-heals. Worth a comment or hard cap.

### 2.8 Minor items

- **Unbounded media-download fan-out**: `CommandPanelState.startMediaDownloads` spawns one `execute` (one yt-dlp process) per URL in a pasted batch — no concurrency cap. A 40-link paste = 40 concurrent yt-dlp processes.
- **`/bin/zsh -lc` for one pipeline** (ActionRunner:373): `terminatePort` loads a full login shell for `lsof | xargs`. `/bin/sh -c` or direct `lsof`+`kill` skips profile evaluation.
- **`WebSearch.boundedData`** appends one byte at a time in an async loop — bounded by cap, but O(n) closure hops.
- **`ProcessOutputLineBuffer.emitCompleteLines`** (:322-328): `firstIndex(of:)+removeSubrange` per line — O(k·n); bounded by `outputLimit`.
- **`UsageRankingStore.save`**: whole-store atomic JSON write synchronously on caller per `recordExecution` — tens of KB, fine today.
- **`AIChatStore`**: whole-history JSON per mutation (off-main already); thread count unbounded.
- **`CommandRanker.ordered`** re-scores every candidate providers already matched, and `localizedCaseInsensitiveCompare` sits inside `sorted` at O(n log n) calls — fine at current scale.
- **Normalized-prefix/raw-string indexing bug (correctness + perf)**: `MacUtilitiesProvider.payload(in:)` and the `DeveloperToolsProvider` copy index the **raw** query by the **normalized** prefix length — `SearchScoring.normalize` folds case/diacritics and collapses non-alphanumerics, so lengths diverge. `"base64!!x"` → payload `"!!x"`. Offsets must be taken on the same string they index.
- **`BrowserProvider.defaultResults`** maps all 18 `BrowserSource` cases with no installed-check — Home offers launchers for uninstalled browsers (codified by `BrowserProviderTests:109`). Product noise rather than a bug, but worth a filter.
- **`openQuickAI` skips `stopTransientPolling`** — leaving Home's timers running under the AI sheet.
- **shelf-scene.ts:199-203** writes five `canvas.dataset.*` strings per rendered frame — dev telemetry in the render loop.

### 2.9 Verified-good (read, no action)

Search pipeline (40ms debounce, generation-cancel, 80/250ms two-phase tiers, per-provider gates + health), adaptive polling (2s→6s→20s under LPM/thermal, only while visible), `Task.detached(.utility)` for metrics/agent/sqlite work, ProcessRunner concurrent pipe drains + process-group kill + SIGTERM→SIGKILL, clipboard `changeCount` short-circuit + bounded payloads + debounced writer, sqlite-copied browser DBs, DNS-pinned SSRF-resistant media downloads, Keychain credentials, BEN2 hash-pinned staged provisioning with rollback, agent installers that preserve unrelated hooks and refuse to clobber foreign plugins, render-on-change three.js scene with zero per-frame allocs.

## 4. Test suite audit — all 39 files read

**Overall: a genuinely good suite.** Most tests exercise state machines, cancellation semantics, persistence round-trips, adversarial input, and filesystem safety — not control presence. Highlights worth keeping: staged-discard reservation safety (ArtifactStore), clipboard hostile-type rejection + coalesced persistence, DirectPaste restore-on-failure ordering, provisioning consent-fingerprint matching, cancellation-before-launch races, camera start/stop generation handling, coordinator stale-search rejection, file-conversion consent/cancel/retry flows, LZ4 adversarial bounds (FirefoxSessionParser).

### 4.1 The structural problem: `CommandRankingTests` test the wrong path

~20 ranking tests drive `registry.results(matching:)` — a test-only method duplicating `completeResults` that production never calls (§1.1.6). The tests are well-written; the implementation under test has already drifted from the real path. Either delete `results(matching:)` and retarget the tests at `immediateResults`+`completeResults`, or make the tests fail loudly if the paths diverge.

Same shape in `CommandContractsTests`: `providerDescriptors()` tests exist solely to exercise a test-only API. And the `ProviderHealthStore` telemetry has rich tests but no production consumer.

### 4.2 Slop tests (the "is the button there" pattern)

- **`ResourcePackagingTests` — mostly string-contains file assertions.** `testPackagingVerifierChecksTheBuiltArtifact` asserts 12 literal strings in a shell script; `testREADMEDocumentsBuildAndOptionalSetup` asserts the README contains marketing phrases ("Persistent local clipboard history"…) and doesn't contain others; `testReleaseWorkflowBuildsAndPublishesVersionedArtifact` grep-pins the CI file. These fail on wording changes, not behavior. Keep `testBuildPackagingDeclaresCameraPurposeAndEntitlement` (entitlement presence is a real gate) and `testPackageDeclaresOnlyCurrentResourceDirectories` (guards resource wiring); cut or consolidate the rest.
- **`TranslationTests:110` — tautology.** `testTypedFailuresHaveDistinctCases` asserts `Set(failures) == Set(failures)` — always true, tests nothing.
- **`DependencyProvisioningTests:18` — near-tautology.** `testCapabilityStatesAreEquatable` checks synthesized `Equatable` conformance.
- **`WindowManagementProviderTests.testEveryPlacementProvidesMetadata`** — asserts title/subtitle/icon strings are non-empty for every placement. Presence check; the neighboring tests already cover the meaningful behavior.
- **`BrowserProviderTests.testBrowserCatalogIncludesMajorBrowserFamilies`** — asserts enum cases exist. Compile-time fact, not behavior.
- **SQL string-shape tests** (`CodexDesktopThreadAdapterTests.testQueryTargetsAuthoritativeDesktopCatalog`, `CursorComposerAdapterTests.testQueryReadsCurrentComposerDataFromCursorDiskKV`) — pin query text, not results; modest residual value in asserting read-only-ness (no INSERT/UPDATE/DELETE). Keep-or-cut by taste.

### 4.3 Weak assertions / non-gates

- **`PerformanceRegressionTests` aren't regression gates.** `measure` without baselines only logs. `testHomePollingWorkload` sleeps **6 seconds** then asserts `memoryTotal > 0` — a slow smoke check that would pass on almost any implementation. Either set baselines or rename out of "regression."
- `testConfigSnapshotsRemainConsistentDuringConcurrentWrites` uses `try?` on the writes it claims to verify — it can pass even if every write throws.
- `CommandPanelStateTests` has several `if case .search = mode { XCTAssertTrue(true) }` — verbose but correct; the tautological branch is stylistic slop, not a hole.

### 4.4 Coverage notes

- No test exercises `mediaURLs(in:)` per-keystroke cost or the `payload(in:)` normalized-index bug — the two real findings in §2.
- Ranking tests can't see the production path's supplemental-dedup behavior (see 4.1).
- `SystemMetricsTests`, `SourceRootLocatorTests`, `SearchScoringTests`, `OperationCoordinatorTests`, `MediaNetworkPolicyTests`, `ProcessRunnerTests` — all real behavior, keep as-is.
