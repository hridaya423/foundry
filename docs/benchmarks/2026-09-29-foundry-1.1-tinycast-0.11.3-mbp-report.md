# Foundry 1.1.0 vs Tinycast 0.11.3 — 29 September 2026

Machine: MacBook Pro, Apple M4 Pro, macOS 27.0, **on battery** (34%); the `--require-ac`
gate was not applied. Both launchers quit before each leg (`--isolate`).

Runner: `scripts/benchmark-launchers.swift` compiled with `swiftc -O`, Foundry leg
pointed at `build/Foundry.app` (this tree's staged release build):

```
benchmark-launchers --only Foundry,Tinycast --bundle build/Foundry.app \
  --runs 30 --warmups 5 --memory-samples 15 --startup-wait 10 --settle 2 --isolate [--reverse]
```

Raw records: `2026-09-29-foundry-1.1-tinycast-0.11.3-mbp-forward.json`,
`-reverse.json`. Tinycast's hotkey was configured once via its own Settings (⌃⌥Space,
persisted as `hotkey.togglePalette`); Foundry used the user's configured ⌘Space.

## Panel show — hotkey post → on-screen window (p50 of 30)

This build keeps the panel mapped (alpha 0) instead of `orderOut` on hide, which
removed ~80–90 ms of window-server surface creation per show vs the earlier
`orderOut` build (~110 ms measured identically on 29 September).

| Order | Foundry | Tinycast | Foundry advantage |
|---|---|---|---|
| Foundry first | 17.5 ms | 66.7 ms | 3.8× |
| Tinycast first | 19.1 ms | 64.7 ms | 3.4× |

Same metric pipeline for both: CGEvent → `kCGWindow` on-screen + alpha + width ≥ 400.
AX-window probe (`axMilliseconds`) corroborates: Foundry 3.4–16.6 ms, Tinycast
64.3–64.5 ms.

## Warmed memory footprint (macOS `footprint`, p50 of 15)

| Order | Foundry | Tinycast |
|---|---|---|
| Foundry first | 120.0 MB | 40.4 MB |
| Tinycast first | 60.5 MB | 40.6 MB |

Tinycast is lighter: ~40.5 MB vs Foundry's 60.5–120.0 MB. Foundry's first-leg
reading is inflated the same way its Raycast-first leg was; the honest claim is
that Foundry is ~1.5–3× heavier, with feature surface (widgets, agents, file
shelf, command catalog) the obvious cause — no claim made.

## Installed size (`du -sk`)

| Foundry 1.1.0 | Tinycast 0.11.3 | Tinycast advantage |
|---|---|---|
| 16,508 KB (16.5 MB) | 13,576 KB (13.6 MB) | ~1.2× |

## Read

- **Latency: Foundry wins.** 17–19 ms vs 65–67 ms hotkey-to-panel is user-visible;
  the keep-mapped change puts Foundry in Raycast's ~18 ms class and ~3.5× ahead of
  Tinycast.
- **Memory + disk: Tinycast wins.** It is the smaller, leaner binary by design.
  Foundry carries more surface; that is a product trade-off, not a defect — but it
  should not be spun into a memory claim.

## Not covered / caveats

- Battery power, not AC — numbers may carry throttling noise; both apps share it.
- Tinycast settings/extensions were defaults; Foundry was the user's configured
  install state rebuilt from this tree.
- Footprint is `footprint` Summary, not user-perceived memory pressure.
